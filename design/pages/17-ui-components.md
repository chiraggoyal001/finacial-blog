# UI Components — The Building Blocks

Think of components like LEGO bricks — each one does one thing well, and you combine them to build pages. Using the same bricks everywhere means the app feels consistent, whether you're on the homepage or deep in your portfolio settings.

## Bento Grid — The Modern Dashboard

Trending

Bento grids are THE layout pattern of 2026. Asymmetric cards of varying sizes, like Apple's WWDC presentations. Perfect for dashboards.

**Bento rules:** Hero card (2×2) always top-left. Supporting metrics fill remaining cells. Use `auto-rows-[140px]` for consistent row heights.

## Glassmorphism — Depth Without Weight

Trending

Frosted glass effects create visual hierarchy while keeping the interface feeling light and modern. Use on overlays, modals, and floating elements.

Glass Card

Frosted overlay

backdrop-blur-xl + bg-background/60

#### When to Use Glass

- ✓ Floating action buttons over content
- ✓ Command palette / search overlay
- ✓ Mobile bottom sheets and drawers
- ✓ Notification banners over charts

#### When NOT to Use

- ✗ Regular content cards (performance cost)
- ✗ Text-heavy areas (reduces readability)
- ✗ Low-contrast backgrounds (glass disappears)

## Command Palette — ⌘K Power User Pattern

Trending

The modern search-and-action pattern. Press ⌘K (or Ctrl+K) to open a unified command center. Essential for power users.

## Component Comparison — When to Use What

Guide

Decision matrices for the most common 'which component?' debates.

ButtonvsLink

Use Button when

Triggers an action (submit, delete, confirm)

Use Link when

Navigates to another page or section

💡 If it changes data → Button. If it changes URL → Link.

DialogvsSheet

Use Dialog when

Critical confirmation or focused input (delete, payment)

Use Sheet when

Supplementary content or settings panel

💡 Dialog = blocks everything. Sheet = slides in alongside.

ToastvsAlert

Use Toast when

Temporary, auto-dismissing success/info feedback

Use Alert when

Persistent warning or error needing user attention

💡 User can miss a toast. User must NOT miss an alert.

CardvsList Item

Use Card when

Rich content with image, stats, actions

Use List Item when

Simple row data with 1-2 attributes

💡 Cards for browsing/exploration. Lists for scanning/comparison.

DropdownvsCommand Palette

Use Dropdown when

Short list of options (<10) in a form context

Use Command Palette when

Large searchable set of actions/pages

💡 Dropdown for forms. Command palette for power-user navigation.
