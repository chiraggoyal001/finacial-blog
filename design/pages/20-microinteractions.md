# Microinteractions

Microinteractions are the **body language** of your UI. When you press a button and it subtly squishes — that's a handshake. When a heart icon pops after you favorite a stock — that's a smile. These tiny moments are invisible when done right and *infuriating* when missing.

## The Microinteraction Catalog

Every recurring interaction in the app, documented.

#### Button Press

Subtle scale-down on press, bounce-back on release.

Trigger: mousedown / touchstartDuration: 100ms down, 200ms up

#### Toggle Switch

Instant visual feedback. The knob slides, the track changes color.

Trigger: click / tapDuration: 200ms spring curve

#### Like / Favorite

Scales up 120%, changes color, then settles back.

Trigger: click / tapDuration: 300ms with overshoot

#### Copy to Clipboard

Icon swaps from clipboard to checkmark, stays for 2s.

Trigger: clickDuration: 150ms swap, 2000ms hold

#### Pull to Refresh

Pull down to reveal a spinner. Release triggers refresh.

Trigger: touch drag downDuration: Follows finger, then 300ms snap

#### Long Press to Delete

Hold to fill a progress ring. Release early = cancel.

Trigger: mousedown holdDuration: 1000ms fill, 200ms confirm

#### Swipe to Dismiss

Drag card horizontally, fade out on release past threshold.

Trigger: touch drag horizontalDuration: Follows finger, 200ms dismiss

#### Success Confetti

After first SIP, KYC completion, or hitting a goal.

Trigger: Milestone achievedDuration: 1500ms, then fade

## Feedback Channels

Microinteractions communicate through four channels. Match the channel to the moment.

#### Haptic (Mobile)

Light tap on toggle, medium on confirm, heavy on error

**When:** Physical actions — toggles, deletes, payments

#### Visual

Color change, icon swap, scale animation

**When:** Every interaction — the baseline feedback

#### Audio

Soft click, success chime, error buzz

**When:** Important moments only — too much sound is annoying

#### Text

'Copied!', 'Saved', 'Added to watchlist'

**When:** When the action isn't obvious from the visual change

## Microinteraction Anti-Patterns

Critical

The most common mistakes that make interactions feel broken or annoying.

✗Button with no active state

✓Add active:scale-[0.97] to all buttons

Impact: Users can't tell if their click registered

✗Toggle without transition

✓Add 200ms spring transition on the knob

Impact: Feels like a broken checkbox from 2005

✗Loading with no feedback

✓Swap icon to spinner, disable button, show text

Impact: Users rage-click, causing duplicate submissions

✗Success without celebration

✓Add checkmark scale-in + green flash + text change

Impact: Users wonder 'did it actually work?'

✗Error without explanation

✓Red border + shake + error text + recovery action

Impact: Users don't know what went wrong or how to fix it

✗Delayed tooltip (> 500ms)

✓Show tooltip after 200ms hover, hide after 100ms leave

Impact: Users move on before seeing helpful information

## The Do's and Don'ts

#### Do

- Add feedback to every interactive element — buttons, toggles, links
- Use spring curves for physical-feeling animations
- Celebrate user milestones — first investment, goal reached, KYC complete
- Match feedback intensity to action importance (payment > toggle)
- Respect prefers-reduced-motion — disable non-essential animations
- Test on real devices — animations feel different on mobile vs desktop

#### Don't

- Animate everything — too much motion causes cognitive overload
- Use haptic feedback on every tap — reserve it for meaningful actions
- Block the UI during animations — users should always be able to interact
- Add sound to microinteractions by default — let users opt in
- Forget loading states — a button that doesn't respond feels broken
- Use different interaction patterns for the same action across screens
